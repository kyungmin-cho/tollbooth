## Authentication and callbacks

Browser bootstrap requires exact Origin and returns a CSRF proof separately from a signed HttpOnly owner cookie. Browser mutations require both; bearer clients keep the original scoped contract. Owner lifetime is 90 days, merchant lifetime one hour, with Secure cookies on HTTPS and SameSite Lax/Strict respectively. Merchant cookies include a credential version hash, so changing the admin secret invalidates prior access. Neither cookie nor raw login secret enters localStorage.

Callback state binds owner/session/nonce/approval expiry. Its nonce hash is committed atomically with the immutable create operation before the order POST. The DO repeats owner/order/state checks and consumes the nonce once before provider activation or safe cancellation. A foreign browser gets a recovery explanation. Redirects do not prove wallet authorization. Existing M1/M2 sessions retain their explicit authenticated activation route.

`public/_headers` supplies CSP, no-referrer, nosniff and frame denial for the SPA. Client credentials remain in memory only; copy-once removes the UI copy. Policies and nonfinancial simulation state are the only localStorage values. Snapshot responses and merchant queries are no-store; unauthorized refresh clears previously displayed merchant data.

## Merchant configuration boundary

The authorized external runtime source currently has neither `MERCHANT_ADMIN_TOKEN` nor `MERCHANT_COOKIE_SIGNING_KEY`; the existing Worker also lacks both. Therefore real remote merchant sign-in deliberately returns `MERCHANT_ACCESS_UNAVAILABLE`/503. Local tests use clearly synthetic values. No secret was invented, printed or sourced elsewhere to bypass this boundary.

For remote merchant acceptance, provision two independent high-entropy values of at least 32 characters in `~/.config/paypal-hackathon/sandbox.env`. Then run `pnpm sandbox:setup --remote` followed by `pnpm exec wrangler secret bulk .dev.vars.remote --config wrangler.remote.jsonc`. The setup preserves the existing owner signing key, copies only allowlisted runtime values and requires the merchant pair together. Do not display or commit the file. This is the remaining configuration gate, not a missing login implementation.

## CPU measurement and limits

`node scripts/verify/profile-mcp.mjs --evidence <private-dir>` profiles 30 legacy connections plus tools/list against the local test server's inspector at port 9232. It records stack samples, not request payloads or credentials. The local profile identifies SDK/schema validation, handler creation, URL and stream handling; local timings are not a remote Free-limit proof.

Immutable Standard Schema JSON conversions and session schemas are created once; HMAC CryptoKeys are bounded caches. Discovery handler configuration is reused without any principal or business metadata, while each MCP request still creates its own server. The merchant bundle is lazy loaded; the Worker bundle is minified. A first attempt to lazy import MCP moved SDK initialization into a request and produced a 76ms remote sample, so MCP is statically imported again. Failed evidence is retained, not discarded from the report.

Ordinary Free Worker requests have a 10ms CPU budget; DO invocations have a separate default 30-second budget. The prior DO 12ms sample is not a 10ms DO-limit failure. Startup time and network wall time are not request CPU. [Worker limits](https://developers.cloudflare.com/workers/platform/limits/), [DO limits](https://developers.cloudflare.com/durable-objects/platform/limits/).

`remote-m4.mjs` uses the already completed M2/M3 session for authenticated status, identical-key replay and terminal close, asserting unchanged ledger and settlement. It never creates an order, authorizes a wallet or sends a new payable call. Discovery and the public/demo/browser-bootstrap APIs are sampled separately. Requests are paced to reduce live-tail drops; sanitized CPU/wall-time rows and per-route p50/max remain in private evidence. New capture/void CPU and an actual browser wallet round-trip are not measured in M4.

The final local result is 155 Vitest tests (11 files) and 10 Playwright scenarios, all passing, with 34 screenshots and green typecheck/lint/build/secret checks. Remote migration 0003 and public UI/CSP/MCP smoke passed. The final deployed version is `74376db0-84f2-41dd-b642-b40f1c6c4cc6`.

The paced measurement on `4d919c09-db0a-4717-b66f-966dfa56f3a6` used 158 requests and retained partial live-tail samples: legacy connection p50/max 1/7ms, modern list 1/5ms, legacy list 0/2ms, existing paid-tool replay 2/5ms modern and 2/4ms legacy, status 0/1ms, terminal close 1/1ms. The final UI-only redeploy has identical Worker/DO/MCP source; its new-version smoke observed a 9ms first modern connection and at most 6ms legacy connection. These samples fit 10ms with only 1ms cold-path headroom; they are not a load or all-POP guarantee. The Worker bundle decreased from the M2/M3 1308.64 KiB (gzip 229.43) to 754.37 KiB (gzip 173.92). Startup is 44ms, separate from request CPU.
