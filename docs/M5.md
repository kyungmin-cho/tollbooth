## Judge path

Open `/judge` from the public navigation. `/run/rehearsal` and `/demo/merchant` need no credentials and clearly simulate the workflow. The real sandbox path needs the judge's own **Personal PayPal sandbox buyer account**, created through PayPal Developer's Sandbox Accounts page. Enter that account's password only on PayPal's sandbox. No owner buyer credentials are published. [PayPal account documentation](https://developer.paypal.com/sandbox-testing/accounts) explains the personal/business distinction and account creation.

Open a USD 5.00 session, ask AI to choose tools, approve the wallet limit, return in the same browser, and run the saved plan through MCP. Default policy allows the 20-cent call and asks before each 35-cent call. Decline stops the run. Re-running the saved plan replays completed identities. Finish captures 90 cents once after all three calls; a separately approved session closed without calls voids its authorization. Cookies retain ownership; a shared URL cannot convey access.

## Capacity and failure behavior

- Orders: 100/day globally, five/hour/owner, admission before provider creation. Existing read/close/recovery remains independent of admission.
- AI: one round/session, three proposed tool calls, 20 daily runs globally, three/owner/day, fixed bounded input, 768 output tokens. Atomic D1 reservation, no refund/retry after uncertainty, UTC reset. Account Free cutoff prevents billed overage; provider exhaustion becomes explicit fallback.
- Execution: four in flight/session and 20 successful-or-running calls, integer budget/reservations and close barrier. Existing snapshot polling pauses hidden/final tabs; pending AI checks every five visible seconds and terminates at persisted completion/fallback.
- Bounded evidence: one AI result per session, exactly three schema-validated calls, argument strings <=1 KiB; no raw model prose/reasoning or provider exceptions retained. UI activity keeps 20 entries and AI results three. No request bodies, credentials, model messages, or payment payloads are application logs. Financial journal/outbox/inbox records are recovery evidence, not disposable logs.
- D1 outage blocks new AI inference; it never permits a replacement inference or modifies DO spending authority. Stale merchant projections remain separate from current DO detail. Unknown capture remains unconfirmed and read-reconciled. No AI inference runs during settlement recovery.

## Sandbox driver

Use `pnpm run sandbox --prepare --ai --origin <deployment-origin> --evidence <private-evidence-dir>`. It saves the real validated model plan alongside the fresh order and approval URL, then stops. `--prepare --zero-use` creates the independent zero-use order. Do not approve wallets programmatically.

After a human approves both wallets, run normal `--resume --ai --approve-ai-calls` and zero-use `--resume --zero-use` with the same origin/evidence. The normal flag consents only to the saved, validated 90-cent AI plan; without it each above-threshold call requires an interactive `yes`. It does not approve PayPal. Verify with `--verify --ai` and `--verify --zero-use`. Verification does not create financial mutations. Preserve the private files and signing key; do not create replacement sessions after an ambiguous outcome.
